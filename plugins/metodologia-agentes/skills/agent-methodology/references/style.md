# No filler

Everything any agent on the project produces is written so that someone can use it, not so that it sounds good. It applies to the interface, the product's texts, the documents, the messages and the code.

## Interface

- No generic AI aesthetics: no gradients, glows or decorative shadows; no emojis; no illustrations, icons or cards that do not inform.
- No marketing phrases ("powerful", "intuitive", "frictionless").
- Every element on screen serves a function.

## Product texts

- Concrete and technical.
- No artificial enthusiasm ("Done!", "Great!") and no phrases that say nothing.
- An error says what happened, the probable cause and how to fix it, not just a code.

## Agents' documents and messages

- Only what is needed and verifiable.
- No praise ("excellent question"), no repeating what was already said, no inflated words ("robust", "comprehensive", "leverage").
- No overuse of bold or bullet points.
- Prompts for another agent or for a new chat go in the message, in a code block ready to copy. As a file, only if they do not fit.
- In the language and form of address the team has agreed on (it is in `CLAUDE.md`).

## Code

- No obvious comments.
- No abstractions or code that nobody uses.
- No invented example data or texts.

## Nothing invented

Not data, not results, not capabilities, not figures that were not measured. If something is not known, say that it is not known and how to find out.

## Assumptions in plain view in the product

Every assumption, interpretation and limitation of the product is declared to the user, on screen and in what is delivered (reports, exports), always, whether it passes or not. What the product does not check is stated clearly, with a notice where it applies.
